# SEO Audit Fixes Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Fix every real, verified finding from the 2026-09-09 `/claude-seo:seo audit` of https://daily-dose-hazel-delta.vercel.app/ — except the one finding the user explicitly ruled out — ranked by value to daily-dose, in phases.

**Architecture:** No new subsystems. Every task edits an existing Astro component/page, `src/lib/imageResolution.ts`, or `vercel.json`, and updates the Vitest regression tests that already assert the behavior being changed. Nothing here touches the publish path (`scripts/pipeline.ts`, `src/lib/llmCuration.ts`, `src/lib/curation.ts`, `src/lib/costTracking.ts`, `src/lib/digestSchema.ts`) — `CLAUDE.md`'s plan-mode-first gate for that path does not apply to this plan.

**Tech Stack:** Astro 5 (`.astro` components/pages), TypeScript, Zod, Vitest, `vercel.json` platform config.

**Spec:** This plan has no separate spec doc — the "spec" is the `/claude-seo:seo audit` findings from this conversation, cross-checked against real source in this repo (every task below cites the exact file/lines verified before writing the task).

## Global Constraints

- **EXCLUDED, do not touch:** The `[Critical] Methodology is orphaned from search and from users` finding (robots.txt `Disallow: /methodology`, no sitemap entry, no nav/footer link). The user explicitly ruled this a known, deliberate, already-decided choice (`astro.config.mjs`'s sitemap filter + `robots.txt.ts`'s comment both cite PR #79) and said to leave it exactly as-is. No task in this plan adds a link to `/methodology` from anywhere, including the new `llms.txt` in Task 3.
- **Private-repo citation decision (user's explicit choice, `AskUserQuestion`):** "Keep repo private, stop citing it." Every link in the live site pointing at `github.com/sairam0424/daily-dose` (a private repo) is a dead link for every real visitor. Tasks 1 and 2 remove these and inline the same substantive information instead of linking out. `package.json`'s `repository`/`bugs`/`homepage` fields are not rendered on the site and are out of scope.
- **Two audit recommendations are excluded, on this plan-writer's own ruling (not yet explicitly confirmed by the user — flagging here in case they want to override it):**
  - Adding Article/CreativeWork schema to story items — conflicts with `src/components/DigestList.astro`'s existing, documented decision ("Deliberately not Article/NewsArticle: these are third-party links this site curates, not original reporting, which would contradict the site's own correct `og:type:website` choice") and `SOUL.md`'s no-fabricated-claims stance.
  - Adding Organization/Person schema — conflicts with `src/components/SiteMeta.astro`'s existing, documented decision ("no formal entity or named author is surfaced anywhere on the site — inventing one would be a fabricated claim") **and** would break an existing passing regression test, `tests/structuredData.test.ts:35` (`"(regression) ships a valid WebSite node on every page type, with no SearchAction and no invented Organization/Person"`).
- **Three more audit-flagged items were checked against real source and could not be confirmed as real bugs — excluded as likely false positives, not fixed:**
  - "Logo alignment bug" — `src/layouts/Layout.astro`'s `.masthead-brand h1` already sets `display: flex; align-items: center; justify-content: center; gap: 0.4rem;`, which correctly centers the logo mark and wordmark. No misalignment reproduces from source. If the user can show a live screenshot of an actual misalignment, that's a new bug report, not this finding.
  - "Archive-index page copy is generic" — `src/components/DigestPreviewCard.astro` already renders each date's real lead-story title (`lead.data.title`) and real `why_read` excerpt per row, not generic boilerplate.
  - "CollectionPage/date schema inconsistency" — `src/pages/archive/index.astro` already has a real `CollectionPage`+`BreadcrumbList` pair (lists dates, so a `CollectionPage` is correct); `src/pages/archive/[date].astro` and `src/pages/index.astro` correctly use a bare `ItemList` via `DigestList.astro` (they list story items, not sub-pages, so wrapping in `CollectionPage` would be the wrong shape); the homepage has no breadcrumb because it is the site root, matching Google's own documented convention of omitting breadcrumbs there. Nothing to fix.
- **Existing regression tests assert the exact current behavior some tasks change.** Every task that changes rendered output updates its corresponding test in the same task — never leave a stale assertion for a later task to discover as a CI failure.
- **Test command:** `npm test` (full suite) or `npx vitest run tests/<file>.test.ts` (single file) — both run against source directly except `*-page.test.ts` files, which read `dist/` and require `npm run build` first (see each task).
- Never fabricate data. Every piece of copy this plan adds is derived from real, already-in-scope fields (`entry.data.title`, `entries.length`, etc.) — never invented text.

async function isImageUrlReachable(url: string): Promise<boolean> {
  const controller = new AbortController();
  const timeout = setTimeout(() => controller.abort(), FETCH_TIMEOUT_MS);

  try {
    const response = await fetch(url, {
      method: "HEAD",
      signal: controller.signal,
      headers: IMAGE_FETCH_HEADERS,
    });
    if (!response.ok) return false;
    const corp = response.headers.get("cross-origin-resource-policy");
    if (corp === "same-origin" || corp === "same-site") return false;
    const contentLength = response.headers.get("content-length");
    if (contentLength && Number(contentLength) > MAX_IMAGE_BYTES) return false;
    return true;
  } catch {
    return false;
  } finally {
    clearTimeout(timeout);
  }
}
